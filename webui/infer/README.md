# drmage 推理平台（交互实验台）

在浏览器里**玩**当前成绩最好的那一版模型：拖条件 → 出图 → 转 3D 看 →
导出 zip。就是一个给人交互的沙盒，不是训练/监控工具。

* 对外名字：**`drmage-1.0-flash-preview`**（实验预览版命名）。
* 路径与 tag **没动**：权重仍在 `models/diff_v2_masked/`，`drmage` 只是展示名，与训练日志、复现文档保持一致。
* 监听：`127.0.0.1:8850`（只绑本机）

---

## 1. 怎么起（服务要你自己拉，会话里起的进程会被回收）

```bash
cd <本仓库根目录>
python webui/infer/server.py
```

然后浏览器打开 <http://127.0.0.1:8850>。想开屏就能出图（省掉首次点击的几秒）：

```bash
python webui/infer/server.py --preload      # 启动时先把默认权重载进来
python webui/infer/server.py --port 8860    # 换端口
```

> 训练**不受影响**：这个服务只读 `models/`、`data/processed/`、`logs/`，
> 从不写训练目录。唯一的写盘：`webui/infer/history.jsonl`、
> `webui/infer/exports/`（每次导出 zip 的磁盘留档，浏览器拦截下载时
> 文件也拿得到）、内存图片缓存。
> 它和训练监控面板（`webui/server.py`，端口 **8848**）是两个完全独立的进程，
> 谁都不依赖谁，可以同时开。

## 2. 界面

**左侧面板**

| 区块 | 说明 |
| --- | --- |
| 条件来源 | 「滑块合成」（自己捏条件）/「真实抽样」（从 val 集真实条件里抽，旁边给真实皮肤对照） |
| 7 个滑块 | 主导色相 + 色相集中度、饱和度、明度、暗/亮/中性色占比 |
| 3 个枚举 | tone / 饱和档 / 复杂度档（取值直接来自 `labelset` 的枚举表） |
| 第二层 | 要不要生成帽子 + 身体 overlay 那 6 个盒子 |
| 采样 | 批量 n、DDIM 步数、η、种子（🎲 随机）、alpha 模式 |
| 后处理量化 | 见下面「量化」一节 |
| 生成 | 按钮 + force 强制 + 进度条 + 错误行 |

**右侧**：生成结果缩略图网格（可切「平面 / 3D」缩略图），下面一条**真实皮肤对照栏**。
点任意缩略图进弹窗：可转的 3D、UV 展开图（可叠面网格）、逐张指标、下载 PNG、复制条件。

3D 视图支持拖拽旋转 / 滚轮缩放 / 双击复位，视角按钮 `front / right / back / left / top / iso`，
另有「第二层」开关和「自转」。

### 「层」开关：同时管预览和导出

结果区标题右边那个「层」下拉，有三处视图、**一个状态源**（前端 `S.layer`）：

| 视图 | 位置 |
| --- | --- |
| `#selLayer` 下拉 | 结果区标题栏，导出按钮左边 |
| `#cbOv` 复选框 | 弹窗 3D 控制条里的「第二层」 |
| 导出按钮文字 | `⬇ 导出 zip（含第二层 / 仅第一层）` |

改任何一处，其他两处和所有缩略图、弹窗 3D、导出 zip 都跟着变。

* **含第二层（默认）** —— 完整的 64×64 RGBA，帽子/外套都在。
* **仅第一层** —— 预览里去掉 overlay 盒子；导出时把第二层那 36 个面覆盖的像素
  （实测 1632 px / 4096 = 39.8%）**整片置为透明**，第一层一个像素都不动。

> 为什么不做成「预览一个开关、导出另一个开关」：那样一定会出现
> 「缩略图看着有两层、导出来只有一层」。既然本质是同一个问题（看几层），
> 就只留一个状态。导出的实际清零在**服务端**做（zip 是服务端现拼的），
> 前端只传 `&layer=base`。

## 3. 权重

下拉里列出 `models/**/*.pt`，标了 kind：

* **`diff_v2_masked/ema.pt`（默认，成绩最好）** — 45.4MB，只存 shadow 权重 + `gstep`/`epoch`，
  是出图该用的那一份（EMA 明显比原始更新的权重干净）。
  e2e 实测：**11.875M 参数 / cond_dim=36 / in_ch=3 / cosine / step=686400 / epoch=311**。
* `diff_v2_masked/latest.pt` — 190MB，含优化器状态，**只拿来续训，别拿来出图**。
* `diff_v2_masked/pre_structloss_step680000_ema.pt` — 接 `region_struct_loss` 之前的对照组。
* `diff_v1/*` — 上一代。

排序规则：先按「推荐优先级」，再按 mtime 倒序。换权重会重新载入（`↻ 重载` 或直接换下拉）。

## 4. 三道闸门（为什么会被拒绝）

采样本身峰值约 1.2GB，真正的风险是**和训练叠加 OOM**。所以 `guard()` 会拒：

1. 已经有一个生成任务在跑；
2. 训练 `status == running`；
3. 可用显存 < **3.0GB**。

被拒时界面上给的是人话原因。`force` 可以硬闯（风险自负）。

## 5. 两个「口径」要记住

**alpha（3 通道模型）** —— 模型只输出 RGB，**透明度不由模型决定**，而是按 UV 模板抽：

| 模式 | 含义 |
| --- | --- |
| `template`（默认） | 按实测频率每张独立抽 UV 模板，**等于训练时的做法** |
| `shared` | 整批共用同一张模板（换条件做对比时更公平） |
| `full` | alpha 全满，看模型画出的 UV 全貌 |
| `none` | 全透明，只用来验证渲染管线 |

模板是两级伯努利：盒级「画不画」× 面级 `full/partial/fill`。

**量化** —— 后处理，只在**可见像素**上吸附：

| 选项 | 说明 |
| --- | --- |
| 不量化（默认） | 保留模型连续输出，细节最多，但唯一色会到 1000+ |
| 全局调色板 K=96 | `models/palette_k96.npy`（真实可见像素的 k-means）。**会过冲**：单张常落到 ~37 色、整体偏灰 |
| 自适应 K=48/32/16 | 按**每张图自己**的配色做 k-means，保留本图色调，通常比全局板好看 |

## 6. HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/meta` | 展示名、GPU、训练状态、权重列表、条件目录、**几何（12 盒子/72 面）**、`face_index`、`overlay_faces`、量化选项 |
| POST | `/api/generate` | 起一个异步任务，返回 `{job}`。`cond` 三种来源：`{mode:'spec', spec:{…}}`（滑块合成，整批复制）/ `{mode:'real', tone:'dark'\|null}`（从 val 抽，可筛色调）/ `{mode:'ref', ref_index:N}`（复刻某条真实条件） |
| GET | `/api/job?id=` | 轮询任务状态 / 结果 |
| POST | `/api/generate_sync` | 同步版（**给探针用**，批量请开小） |
| POST | `/api/reload` | 换/重载权重 |
| GET | `/api/img?key=` | 取图（64×64 RGBA PNG） |
| GET | `/api/real?n=&seed=&tone=` | val 集真实对照 |
| GET | `/api/export?keys=&layer=` | 导出 zip（含 README.txt）。`layer=base` 时第二层整片置透明，缺省 `all` |
| GET | `/api/history?limit=` | 最近生成记录 |

## 7. 自检与探针（改完代码怎么验）

全部在 `webui/infer/_probe/`：

```bash
# 端到端接口自检（自己起服务 → 打 40+ 项断言 → 自己收尾）
python webui/infer/_probe/_e2e_run.py --port 8850

# 真实浏览器验收（自己起服务 + 起 headless Chrome → DOM + canvas 像素断言）
node webui/infer/_probe/probe_infer.js
```

**想验「改完的新代码」而用户实例还占着 8850 时**，换个端口跑，别去动人家：

```bash
$env:INFER_PORT = "8851"        # probe_infer.js 读这个
node webui/infer/_probe/probe_infer.js
python webui/infer/_probe/_e2e_run.py --port 8851
```

> 静态资源是 `Cache-Control: no-store`，**改 CSS/JS 只要 F5**；
> 但改 `server.py` / `engine.py` **必须重启服务**，因为它只在你启动时载入一次。

**为什么探针要自己起服务**：会话里起的后台进程活不过一次调用（Job Object 连坐），
所以「起服务」和「打接口」必须在同一条命令里完成。

**端口已被占用时会自动复用**：如果你自己正开着平台（本项目最常见的情形），
这两个脚本会检测到 8850 上跑的就是本平台，于是**直接拿它来自检**，
既不启第二个进程、也不会在收尾时杀掉你的服务。
只会在「端口被非本平台的进程占用」时才停下报错。

> 踩过的坑：最初它们只是「端口非空就退出」，结果你自己开着服务时，
> 自检会莫名其妙报 exit=1，看起来像代码坏了。**别把「环境已有服务」当成失败。**

其余取证脚本（一次性用，留在库里备查）：

| 脚本 | 干什么 |
| --- | --- |
| `_preflight.py` | 开工前取证：条件向量分布、`ema.pt` 能不能载、真跑采样出棋盘对照图 |
| `_seam.py` | 用 500 张真实皮肤验证 6 个面的 3D 朝向（D4 正方对称群 + 坐标下降） |
| `_diag.py` | 查权重里到底有哪些键（`gstep` vs `step`）、`face_index` 与几何是否一致 |
| `_launch.py` | 手动 `start/stop/wait` 服务（调试用） |

**探针里那条最要紧的断言**：
「`yaw=pitch=0` 的 3D 渲染」必须与「前视拼图 `raster()`」**逐像素一致**（实测差异 = 0）。
`raster()` 用的是已被目视确认过的 2D 前视图口径；3D 要复现它，就同时证明了
投影公式、面朝向（`_corners`）、UV 矩形轴序、仿射贴图四件事全对。
贴图用**合成图集**（每像素唯一），所以一像素错位都会被抓到，也不受模型随机性影响。

围绕这条还有几条互补断言：

| 断言 | 抓什么 |
| --- | --- |
| 第一层 3D == 2D 拼图（差异 0） | 投影 / 面朝向 / UV 轴序 / 贴图裁剪 |
| **染色图集**采样 4 个面中心 | 每个面是否取对了**自己**的 UV 矩形（第一层 head=蓝/body=黄，第二层 hat=红/body_ov=绿） |
| 正交视角各 12 面、斜视角 36 面 | 背面剔除与旋转 |
| 第二层包住第一层（露出 0 px） | overlay 外扩方向 |
| 含第二层差异 < 30% | 灾难性错贴（忘裁剪会到 ~92%） |

**为什么含第二层不做逐像素对比**：MC 的第二层是把同一张 UV 贴在**膨胀后**的盒子上
（head 的 8×8 贴到 9×9 几何），纹理本就该整体拉伸 ~12.5%——这是 MC 的真实语义，
而 `raster()` 这个 2D 拼图不模拟外扩。两者叠加 → 含第二层时逐点都不同（实测 20.3%），
这是**正确行为**，所以那一档只看量级。

**一条踩过的坑，值得单独记住：「用 `hidden` 当开关」的元素，必须额外验「没触发时它不可见」。**

`.modal{display:flex}` 是作者样式，会**盖过** UA 样式表里的 `[hidden]{display:none}`
（作者样式优先级高于 UA 样式）→ 弹窗在**页面一打开**时就显示出来，里面还是空的。
而当时的探针只验了「点缩略图能打开弹窗」（这条一直是绿的），
**从没验过「没点的时候它不该在屏幕上」**，所以这个 bug 一路溜到用户手上。
现在 `style.css` 里有一条 `[hidden]{display:none!important}` 兜底，
探针也补了三类断言：boot 时 `#modal/#realBox/#err` 必须 `display:none`、
生成结束后 `#prog` 必须收起、点关闭后 `#modal` 必须重新隐藏。

判据要用 `getComputedStyle(el).display`，不要用 `offsetHeight>0`：
后者对 `display:none` 为 0，但对「被父级裁掉」的元素同样为 0，容易误判。

**同一个病根的第二个病例（更值得记）：空 `catch` 把错误吞掉。**

`paintCells()` 曾经写成

```js
for (const c of _cells) { try { c.card.__render(); } catch (e) { /* ignore */ } }
```

但 `_cells` 里存的是 `{ cv, item, opt }`（没有 `card`，也没有 `__render`）
→ 读 `c.card.__render` 直接 `TypeError` → **被那个空 catch 全部吃掉**。
结果：**所有缩略图 + 整个真实对照栏全空白**，控制台一声不响，探针全绿（它只数了 canvas 数量）。
用户一打开就看见了。

两条教训：

1. **`catch (e) { /* ignore */ }` 不要写成完全静默。** 至少 `console.error` 一次，
   或者像现在这样把每格的 Promise 收集起来 `await`、让失败可见。
2. **断言要验「画出来了什么」，不是「有没有这个元素」。** 现在探针会读每个缩略图的
   `getImageData` 数不透明像素（必须 >0），并额外检查 backing 尺寸不再是 `300×150`
   这个「从来没被绘制过」的默认值。
   「元素存在」和「元素有内容」是两件事，这个项目上已经栽过两次。

**第三个病例（本轮，值得单独记）：判据选错了量纲，「有内容」也会误判。**

给「层」开关写断言时，我先用了「切到仅第一层后不透明像素变少」。结果两条 FAIL。
诊断打印出来才看清：弹窗里含二层 `171041` px、仅一层 `170710` px —— **只差 331（0.15%）**。

原因是这个功能天生如此：**overlay 的 UV 有 80.5% 是透明像素**，
而外扩只有 0.25/侧。真实皮肤的 alpha 一遮，去掉第二层后轮廓几乎不动。

改用**染色图集 + 颜色归属**后立刻灵敏：弹窗里 `hat.front` 的红像素 `32560 → 0 → 32560`。

| 想验的东西 | 别用 | 该用 |
| --- | --- | --- |
| 某一层有没有被画出来 | 不透明像素数（真实 alpha 下两层的轮廓几乎重合） | 染色图集里那片纯色的**像素数** |
| 某个面取对没取对 UV 矩形 | 面积 | 采样面中心像素的**颜色** |
| 缩略图有没有被重画 | 面积 | 像素**指纹**（逐像素累积哈希） |

另外注意 `raster()` 前视拼图**不模拟第二层的几何外扩**，所以 flat 模式下
两层的不透明面积几乎相等 —— **凡是要用面积/轮廓分辨两层的断言，必须走 3D**。

## 8. 模型当前质量：方差主要来自「随机」，不是「条件」

> **口径先说清楚**（这里连着踩了两次坑）：判「结构」必须看**正视图人形**，
> **不能看 UV 展开图**。UV 图集是按 MC 布局摊开的 64×64，人眼读不出结构——
> 色块只有在人形上才拼成一个人。
> 也不能拿「邻域色差」这类**标量**代替眼睛：噪点图和干净图的唯一色数都在 1600~1800，
> 标量根本区分不开（判据选错量纲，连着栽过两次）。
> 现在统一的口径是 `_frontal_ab.py` 里的：
> **只画第一层 6 个 front 面、NEAREST 放大 10×、不量化**，
> 与前端 `raster()` 同源，而探针已证明 `raster()` 与 3D(`yaw=pitch=0`) **逐像素一致**。
> 结构度 = 皮肤像素格 4 邻域几乎同色的边占比；真实皮肤 ≈ 0.41~0.48。

### 8.1 方差分离：换随机 vs 换条件

`_rand_vs_cond.py`，每组 16 张，n=1（保证同 seed 下 alpha 与初始噪声逐位相同）：

| 组 | 单独变的那个量 | 均值 | 标准差 | 极差 |
| --- | --- | --- | --- | --- |
| **S** | 条件固定 `val#2261`，**换 16 个 seed** | 0.264 | **0.130** | 0.101 ~ **0.601** |
| **C** | seed 固定 1234，**换 16 条真实条件** | 0.204 | 0.089 | 0.088 ~ 0.393 |
| — | 真实皮肤（参照） | 0.413 | 0.179 | 0.194 ~ 0.723 |

**标准差之比（随机 / 条件）= 1.46** → **输出质量主要由「抽奖」决定，条件权重更小。**

两条最直观的证据：

* 同一条条件 `val#2261`（色相 **217°，蓝紫**），只换 seed：最差 `0.101`（绿雪花）、
  最好 `0.601`（干净的深蓝人形）——**差 6 倍，且最好那张比真实皮肤的均值还高。**
* seed 固定时换 16 条条件，**16 张的骨架是同一个模子**（都是白灰色人形轮廓），
  条件只负责换色。**骨架是种子给的，不是条件给的。**

### 8.2 所以「真实抽样比滑块好看」是怎么回事

不是色相、不是饱和度、不是直方图形状、不是权重装错（这些都测过，全不成立）。
是**掷骰子的次数**：

* 「真实抽样」= **8 条不同条件 × 8 个种子** → 两个变量同时在动，撞到好组合的概率高
* 「滑块合成」= **1 条条件 × 8 个种子** → 只动种子，一条条件定生死

所以滑块出图难看时，**多点几次「生成」（换 seed）就能明显改善**。
实测同一条 229° 滑块条件：seed=1234 → 结构度 0.232，seed=777 → **0.321**。

### 8.3 但整体质量离真实仍差一截

两组生成的上四分位都在真实皮肤的下四分位附近，而真实皮肤的最小值 0.194
比生成的一大批（0.088~0.16）高一倍。**这不是「换哪个条件」能解决的，是模型本身的问题**
—— 正是下一轮 `region_struct_loss` + `palette_concentration` + 余弦 LR 衰减续训要解的。

### 8.4 复核脚本

```bash
python webui/infer/_probe/_frontal_ab.py    # 正视图人形对比（真实抽样 / 滑块 / 单条重复 / 换 seed）
python webui/infer/_probe/_rand_vs_cond.py  # 方差分离：换随机 vs 换条件
python webui/infer/_probe/_repro_ab.py      # 逐字复刻用户那两张截图
```

> **「色相集中度」滑块的语义是反的**（顺带记下）：
> `vector_from_spec` 里 `sigma = 360 × hue_spread`，值越大直方图越**平**，
> 但 `SPEC_DEFAULTS` 的注释和界面标签都写「越大越集中」。
> 不过它**不是**质量问题的原因 —— 0.02 拉到 0.60，难看的样子并没有质变。

### 顺带修掉的一个真 bug

「真实抽样」模式下那个「跟随上方色调筛选」复选框**一直是失效的**：
前端 `collectReq()` 传了 `cond.tone`，服务端只读 `cond.mode` / `cond.spec`，`tone` 被丢掉。
已修（`gather_cond(..., tone=)`），连带两处：

* 筛完 tone 后条数可能 < 请求的 `n` → 必须以 `cond.shape[0]` 为准，
